The FILE

People have started to plan trips with AI agents, and the agent has to keep each trip somewhere. It could keep notes in a document. With the Agloe format, it knows what is worth recording and how each record relates to the rest.

  1. What to record, and how

    A FILE lists PERSONs, PLACEs, OPTIONs, WAYs, WANTs, FACTs and DECISIONs. It can list BUDGETs, CAPABILITIES and OBJECTs too.

    Each record has an id, and one record names another by its id. The FACT about the show names its OPTION, and the WANT names the PERSONs who hold it.

    The schema defines the structure, and the vocabulary defines each term.

  2. A trip that is half planned

    People plan a trip in pieces. A traveler can book one part while another is open. An agent can record what is booked and what is only on offer. It can leave out what nobody knows yet, and the report names what is missing.

  3. What each person wants, and what delivers it

    An agent records what each PERSON wants apart from the OPTIONs that could deliver it. A WANT can be a must for one PERSON and a must-not for another. For each OPTION, the agent records how well it delivers each WANT, from 0 to 10.

    The agent can list each restaurant and show it finds, and choose none. This FILE has five OPTIONs and no DECISION.

    Today a WANT is a must or a must-not for each PERSON. Preferences in between are not in the format yet.

  4. What an OPTION requires

    An agent can record what an OPTION requires. In the examples, each visitor to the Skydeck needs a ticket, and bag drop for the flight closes 45 minutes before it leaves. One drive to the dunes needs somebody who can drive a manual car. Another needs the car itself.

    More that an agent can record

    A cab is listed, but nobody has recorded how long it takes.
    An agent can leave the travel time out. If Alex and Sam leave the museum at 3:30 pm, they have 45 minutes to reach O'Hare by cab.
    From noon to 6:00 pm, only the Blue Line leaves straight for O'Hare.
    An agent can mark the list of direct routes to O'Hare that afternoon as COMPLETE. Without that mark, a faster way might still exist.
    The Blue Line can take up to 80 minutes.
    An agent can record a range for a ride that the travelers do not control. If Alex and Sam leave at 3:00 pm and the ride takes 80 minutes, they reach O'Hare five minutes after bag drop closes.
    Alex and Sam have decided to go up the Skydeck.
    The agent records that DECISION as a LOCK. For the trip to work, Alex and Sam must both visit the Skydeck.
    From 6:00 pm on Wednesday, cancelling the room costs 189 dollars.
    An agent can record dated cancellation fees in the BOOKING. On Monday the report lists that DEADLINE, with 189 dollars at STAKE.
    The trip money is capped at 200.00 USD.
    An agent can record who may draw on a BUDGET, and a cap on it. The report adds up what is paid and what is still to buy.

The COMPILER

A plan for one traveler on one day fits in an agent's head. Each added traveler and OPTION multiplies the choices, so the agent hands the checking to the COMPILER.

  1. How fast the choices grow

    The FILE for three travelers has five OPTIONs. Each traveler is in each OPTION or out of it. That makes 15 yes-or-no choices, and 32,768 ways to answer them. Each way still has to fit the times and the routes.

    The COMPILER uses a solver for the search. It is deterministic: it gives the same answer for the same FILE each time.

  2. What the COMPILER answers

    Today the COMPILER reads a trip file and gives one of three answers, each with its evidence.

    • FEASIBLE: the trip works. The report shows a plan, and warns when the plan holds only if uncertain durations stay short.
    • INFEASIBLE: the trip cannot work. The report names the FACTs, WANTs and DECISIONs that clash.
    • UNDETERMINED: the file does not say enough to tell. The report names what it would have to say for the trip to work.

    The rules say exactly what it checks, and every trip under examples/ is one of its tests.

    $ uv run agloe check pages/files/three-travelers.json

    FEASIBLE: this trip works.

Saturday 15 May 2027 (times in America/Chicago)
  7:00 pm to 8:30 pm: Dinner at the deep-dish place, Alex and Sam
  7:00 pm to 8:00 pm: Dinner at the tavern, Jo
  9:00 pm to 11:00 pm: Blues on the rooftop, Alex and Sam
  • Check a trip in your browser At the start, bag drop closes at 4:15 pm. Change when Alex and Sam leave the museum or how long the train takes, and the reference checker answers for the new FILE.
  • How a rule is built Each rule is a sentence on the rules page, then code in a slow checker, then code in a fast checker. The two checkers must give the same answers.
  • How an answer is decided A FILE can leave things out. The COMPILER looks for a plan that works in the worst case and, if it finds none, in the best case.

Check a trip yourself

You can run the COMPILER from a copy of the repository. You need git and uv.

Every example is on the examples page, with its report.

git clone https://github.com/ian-c-leonard/agloe.git
cd agloe
uv run agloe check examples/flight-home/works.json
uv run agloe check examples/a-must/cannot-work.json

The OPTIMIZER

The OPTIMIZER is planned for release 0.2 and is not built yet. It will rank the plans that work by how well they deliver what each PERSON wants.

  1. Two plans that both work

    The plan that the COMPILER shows for the three travelers works. Another plan works too: the Skydeck for Alex, dinner at the deep-dish place for Alex and Sam, and the show at the club for Sam and Jo. Jo keeps away from heights in both. Jo hears blues at the tavern, 3 out of 10, or at the club, 9 out of 10.

    The OPTIMIZER will show each PERSON's SCORE beside the total. It will flag plans where one PERSON scores much lower than the others.
