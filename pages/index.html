0.0 The FILE

A standard format that represents a trip and all its nuances, readable by people and machines. It is the lasting record.

A FILE lists PERSONs, PLACEs, OPTIONs, WAYs, WANTs, FACTs and DECISIONs. The vocabulary says what each term in capitals means.

0.1 The COMPILER

            
A compiler that checks the whole plan and explains every conflict.

            
The report is made for an AI agent that plans the trip, more than for a person. Its evidence is a plan, or the records that rule out every plan, or what the FILE would have to say. As data, it names each record by its id. The agent changes the FILE and checks again.

            
The first release is tested by an agent that plans a trip alone. It writes the FILE, reads the COMPILER's reports, and ends with a FEASIBLE TRIP, with no other help.

        The compiler
        
One of three answers, each with its evidence.

        
    
          
  • FEASIBLE: the trip works. The report shows a plan, and warns when the plan holds only if uncertain durations stay short.
    • 
          
  • INFEASIBLE: the trip cannot work. The report names the FACTs, WANTs and DECISIONs that clash.
    • 
          
  • UNDETERMINED: the file does not say enough to tell. The report names what it would have to say for the trip to work.
    • 
        

        
The rules say exactly what it checks, and every trip under examples/ is one of its tests.

      

      

        
AI agents are starting to plan trips. An agent can seat eight friends at dinner in its head. Seating 800 is different: it needs the guest list written down, the rules codified, and something that checks every seat against every rule. A real trip is the 800 case: many people, legs, bookings and times, all affecting each other.

        
People planning without AI benefit in the same way. See the roadmap for what each release contains.

      

    

  


  

    

      

        Method
        
How a rule is built

        
Each rule is a sentence on the rules page, then code in a slow checker, then code in a fast checker. The two checkers must give the same answers.

        
See one rule in each form

      

      
        
    
          
  1. The ideaA sentence in everyday words.
    2. 
          
  2. The wordsThe same sentence on the rules page, in defined terms.
    3. 
          
  3. The slow checkerChecks every possible plan against the sentence.
    4. 
          
  4. The fast checkerStates the sentence as logic and gives it to a solver.
    5. 
        

      
    

  


  

    

      

        The standard it is held to
        
What it must be

      

      
    
        
  • Trustworthy. Anyone, person or agent, can check any trip, including one an AI drafted, and rely on the answer.
    • 
        
  • Flexible. It works for any kind of trip.
    • 
        
  • Whole-lifecycle. It covers the first idea, planning, booking, the live trip, recovery when things go wrong, and the record afterwards. The file keeps the agreed plan, the current forecast and what actually happened.
    • 
        
  • Intuitive. It is easy to read and understand.
    • 
        
  • Multiplayer. Several people and their agents share one plan. They propose changes, the file records what the group decided and why, and the trip stays fair to everyone.
    • 
        
  • Open. It imports what travelers already have, publishes to the tools they already use, and hands purchases to the services that sell them.
    • 
        
  • Durable. The file outlives any app, the way a calendar file does.
    • 
        
  • Agent-ready. AI agents write the file and use it as shared memory across sessions and tools.
    • 
        
  • Self-explaining. Every finding shows its evidence, and what is still missing.
    • 
        
  • Deterministic. The same file gives the same answer on any machine, on any day.
    •

        In the open
        
How it is built

        
Ian Leonard designs Agloe and makes its product decisions. AI agents do much of the building: Claude Code writes the code, and Codex reviews each step and each release. The principles and decisions are public, so anyone can see why Agloe works the way it does.

      

    

  


  

    

      

        A town that was not there
        
The name

        
Agloe was a town that appeared on maps of New York State but did not exist. Mapmakers invented it in the 1930s to catch anyone copying their maps. Agloe the compiler catches the parts of a plan that are not really there.
