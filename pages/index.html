0.0 The FILE

A standard format that represents a trip and all its nuances, readable by people and machines. It is the lasting record.

A FILE lists PERSONs, PLACEs, OPTIONs, WAYs, WANTs, FACTs and DECISIONs. The vocabulary says what each term in capitals means.

0.1 The COMPILER

            
A compiler that checks the whole plan and explains every conflict.

            
The report is made for an AI agent that plans the trip, more than for a person. Its evidence is a plan, or the records that rule out every plan, or what the FILE would have to say. As data, it names each record by its id. The agent changes the FILE and checks again.

            
The first release is tested by an agent that plans a trip alone. It writes the FILE, reads the COMPILER's reports, and ends with a FEASIBLE TRIP, with no other help.

An optimizer that finds the best version for the priorities people set.

Why Agloe

        
AI agents are starting to plan trips. They need three things: a lasting place to keep the plan, codified rules that check their work, and a way to say what people want rather than only what is possible. People planning without AI benefit in the same way.

      

      
    
        
  1. 
          
    
            
    The FILE keeps the plan
    
            
    Agents can read and write far more detail than people, but they forget. Conversations get compressed, sessions end, and people switch agents. The plan must live somewhere lasting that any agent or person can pick up.
    
            
    A FILE is JSON, and a published schema says what a valid one holds. A person can read it, and so can any agent or program. Each time an agent learns something, it adds a record.
    
          
    
          
        
    2. 
        
  2. 
          
    
            
    The FILE says what people want
    
            
    A FILE keeps what a PERSON wants apart from the OPTIONs that could deliver it. Alex must have deep-dish pizza, and that WANT names no restaurant. Each dinner is an OPTION, and a FACT says whether it SATISFIES the WANT.
    
            
    An agent can swap one dinner for another, and the WANT stays. If no dinner in the FILE fits, the COMPILER says what to look for:
    
            
    The trip works if another OPTION that SATISFIES deep-dish pizza is found for Alex.
    
          
    
          
          
    
            
    A FILE can also say
    
            
    
              
    
                
    A cab is listed, but nobody has recorded how long it takes.
    
                
    A FACT that the FILE does not state is unknown, unless a COMPLETE set settles it. The COMPILER never fills one in.
    
              
    
              
    
                
    The Blue Line is the only way to O'Hare.
    
                
    A FACT can state that a list is COMPLETE. Without that FACT, another way might exist, so the COMPILER cannot answer INFEASIBLE.
    
              
    
              
    
                
    The Blue Line can take up to 80 minutes.
    
                
    A CONTROLLABLE duration is ours to choose; a CONTINGENT one the world chooses. The report warns when a plan holds only if the ride stays short.
    
              
    
              
    
                
    The seller has two places left at 32.00 USD.
    
                
    An OFFER grants nothing. A BOOKING secures the right, and the report says who still has to buy.
    
              
    
              
    
                
    Alex and Sam are going up the Skydeck.
    
                
    A LOCK is a DECISION. A LOCK stays until a later DECISION undoes it; no FACT undoes it.
    
              
    
              
    
                
    From 6:00 pm on Wednesday, cancelling the room costs 189 dollars.
    
                
    A BOOKING records its dated terms, such as what cancelling or changing costs on each date. The report lists each DEADLINE.
    
              
    
            
    
            
    The vocabulary defines each term, and the examples show each one in a FILE.
    
          
    
        
    3. 
        
  3. 
          
    
            
    The COMPILER checks the whole plan
    
            
    An agent can seat eight friends at dinner in its head. Seating 800 is different: it needs the guest list written down, the rules codified, and something that checks every seat against every rule. A real trip is the 800 case: many people, legs, bookings and times, all affecting each other.
    
            
    Neuro-symbolic planning pairs a language model with symbolic tools, such as a solver (Kambhampati et al., 2024). Agloe splits the work that way: the agent writes the FILE, and the COMPILER checks it with a solver.
    
            
    The same answer every time, with the reason for every problem it finds.
    
          
    
          
        
    4. 
        
  4. 
          
    
            
    The OPTIMIZER finds the best plan
    
            
    A plan can work and still be wrong for the people on it. Travelers need to state their priorities, so the best version can be found and its trade-offs shown.
    
            
    Every ranking shows each PERSON's own SCORE beside the total, so nobody's loss hides in a sum. The ranking flags any ITINERARY in which one PERSON's SCORE trails far behind the others, or in which the same PERSON loses every choice.
    
            
    The OPTIMIZER is release 0.2. It is not built yet.

What the COMPILER answers

        
Today the COMPILER reads a trip file and gives one of three answers, each with its evidence.

        
The rules say exactly what it checks, and every trip under examples/ is one of its tests.

        
See the roadmap for what each release contains.

      

      
    
        
  • FEASIBLE: the trip works. The report shows a plan, and warns when the plan holds only if uncertain durations stay short.
    • 
        
  • INFEASIBLE: the trip cannot work. The report names the FACTs, WANTs and DECISIONs that clash.
    • 
        
  • UNDETERMINED: the file does not say enough to tell. The report names what it would have to say for the trip to work.
    •

            Each rule is a sentence on the rules page, then code in a slow checker, then code in a fast checker. The two checkers must give the same answers.
            
      
          
    1. The ideaA sentence in everyday words.
      2. 
          
    2. The wordsThe same sentence on the rules page, in defined terms.
      3. 
          
    3. The slow checkerTries every possibility, and checks each against the sentence.
      4. 
          
    4. The fast checkerStates the sentence as logic and gives it to a solver.
      5.

            How an answer is decided
            A FILE can leave things out. The COMPILER looks for a plan that works in the worst case and, if it finds none, in the best case.
            
    
              
    The worst caseThe best caseThe answer
    
              
                
    a plan worksa plan worksFEASIBLE
    
                
    no plan worksa plan worksUNDETERMINED
    
                
    no plan worksno plan worksINFEASIBLE
