How an answer is decided

A FILE can leave things out. The COMPILER first looks for a plan that works in the worst case. If it finds none, it looks in the best case.

What is unknown

A FACT that the FILE does not state is unknown, unless a COMPLETE set settles it. The COMPILER never fills one in.

A possible world is one way that all the unknown FACTs could turn out.

What can be missing

  • With no stated duration, an OPTION or a WAY might take any length of time.
  • Travel that the FILE does not list might exist between any two PLACEs, and take any length of time.

Every kind of unknown FACT

The three answers

  • FEASIBLE: one ITINERARY, with its way to pay, works in every possible world.
  • INFEASIBLE: no ITINERARY works in any possible world.
  • UNDETERMINED: no ITINERARY works in all of them, and the COMPILER cannot rule the TRIP out.

Two cases settle the answer

The worst case
An unknown duration has no limit. No unlisted WAY exists.
The best case
Every unknown start is free, and every unknown duration and access cutoff is zero. An unlisted WAY joins any two PLACEs and takes no time, except where a COMPLETE set of travel says there is none.

A plan that works keeps working when a ride takes less time, or when more ways exist. So a plan that works in the worst case works in every possible world. If no plan works in the best case, none works in any.

What an UNDETERMINED report asks for

The report names unknown FACTs that could make the trip work. A set of unknown FACTs is enough when the TRIP is FEASIBLE with those FACTs turned out well and every other unknown FACT as in the worst case.

Which sets a report lists

A bag or another OBJECT might be moved by a transfer that the FILE does not list. The COMPILER does not work out whether such a transfer could bring it in time. So UNDETERMINED can be said of a TRIP that no transfer could save. FEASIBLE and INFEASIBLE are never said wrongly.
